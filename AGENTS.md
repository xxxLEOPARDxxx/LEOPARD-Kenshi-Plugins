## Полные двуязычные описания и один номер выпуска (пользователь,30.10.2026)

- Один подготовленный выпуск = одно повышение номера на единицу относительно опубликованного. Исправления и пересборки до публикации остаются в той же версии. MCM: опубликованная версия9, весь текущий пакет изменений — версия10, не11. Номер API не является номером выпуска.
- Для каждого изменённого мода готовить полные, одинаковые по смыслу русское и английское описания в прежнем стиле Claude: разделы возможностей, управления, настроек и совместимости; BBCode-заголовки, списки и выделенные начала пунктов. Новые функции включать в основной список, а не приписывать после настроек.
- В начале описания форка указывать оригинальный мод, автора и ссылку на оригинал. У каждого изменённого мода/форка — отдельный раздел изменений текущей версии на обоих языках. В README сохранять подробный справочник и двуязычные изменения версии.
- release_notes.json содержит текущие EN/RU изменения; changelog.json сохраняет историю версий и одну полную двуязычную заметку выпуска. Отсутствие заметки — ошибка подготовки, а не повод подставить «ВерсияN».
- Steam: основное английское описание и отдельный русский перевод; двуязычный changelog только у первой отправки, без второй записи для перевода. Nexus: оба полных языка в общем файле описания, пользователь публикует сам. До его ссылок Steam не публиковать.
- Описания для игроков не заменять техническим журналом реализации: внутренние функции, таймеры, размеры буферов и Debug относятся к README. Исключение — раздел SDK у MCM. Перед упаковкой проверять все новые функции, обе локали текста, полный changelog, BBCode и лимит Steam; не ограничиваться CRC архивов.

## Авторство, история форков и каталог MCM (уточнение пользователя, 30.10.2026)

- В описании каждого форка отдельно показывать: автора оригинала, явную благодарность ему, ссылку на оригинальный мод и отдельно подписанную ссылку «Исходники оригинала». Ссылка под названием мода не заменяет явного блока исходников. Неподтверждённые репозитории не выдумывать: честно указывать поставку кода с оригиналом и реальную страницу распространения.

Локальные, отключённые и разрабатываемые сборки обозначать отдельно. Каталог и fork_catalog.json, генератор и валидатор — в ours/tools/workshop с синхронизацией workshop.
