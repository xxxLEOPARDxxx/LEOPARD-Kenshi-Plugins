# Диагностика владельца и несовместимых стопок

Пользователь сообщил о метке «украдено у собственного персонажа» после
продажи и о редких предметах после обычного подбора, которые не складываются
даже вручную. Точного воспроизведения второго случая пока нет; пользователь
предложил играть с журналом и сообщить сразу после повторения.

## Что уже известно

- В Item нет отдельного stolen-bit: Native вычисляет результат по владельцам.
- Buyback учитывается отдельно. Значение его map пока сохраняем как сырой int,
  не объявляем ценой и не делаем вывод о недоплате по одному tooltip.
- Native базовый canStackWith после isSameAs допускает два действительно чистых
  предмета без сравнения владельцев. Rotate добавляет проверку ориентации.
- BetterLooting ground pickup ставит обычный PICKUP-приказ. Виновник не найден.

## Подход

Scoped read-only CLI уже подготовлен для фаз before_drop/after_pickup/after_sale.
Он полезен при воспроизводимом случае. Для редкого случая добавляем журнал
событий в существующий Rotate Items: там уже проходит проверка совместимости
и доступны оба предмета и их настоящие состояния поворота. Это решение агента,
основанное на предложении пользователя; новую игровую механику не вводим.

## Требования к журналу

- Управляется существующим Detailed log, default0, последняя настройка MCM.
- Результаты совместимости, владельцы, количество и заряды не меняются.
- Только поток интерфейса; не писать в общий DebugLog из фонового потока.
- События проверки пары и перехода между инвентарями, без кадрового обхода.
- В записи: полный hand, SID/указатели прототипа, изготовитель/материал,
  количество, заряды/качество, размеры, proper/current owner, поворот,
  результат исходного предиката и дополнительного ограничения Rotate.
- При безопасной доступности: раздел/лимит стопки и вызывающий модуль/RVA.
- Ограничение частоты и дедупликация в фиксированной памяти; выключенный
  журнал не снимает дополнительные свойства, не форматирует строки.
- Никаких автоматических исправлений theft/owner, пробных перемещений или
  виртуальных денежных операций. Ошибки диагностики не выключают Rotate.

## Проверка и выпуск

Тестировать неизменность поведения, default-off, лимиты/дедупликацию,
различение native rejection/rotation mismatch/capacity, жизненный цикл и
поток. Затем VC10, импорты установленного KenshiLib/MyGUI и source review.
Личный конфиг сохранить, три локали обновить. Диагностическую сборку сначала
установить локально; Nexus/Steam без новых ссылок не публиковать. Номер
публичного выпуска не менять после каждой правки.
