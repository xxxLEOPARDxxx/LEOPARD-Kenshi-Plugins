## Происхождение исходников и локальные правки

Каталог `D:/DEV/Kenshi/KenshiLib-src` не является рабочей копией Git. Сравнение
всех файлов с исходниками тега 0.5.1 после нормализации CRLF/LF дало 1330
совпадающих файлов, три изменённых файла и ни одного отсутствующего файла
официального дерева. Это проверка соответствия снимка, а не его Git HEAD.

Изменены только:

- `Include/kenshi/AI/AIPackage.h` и `Include/kenshi/AI/Blackboard.h`: общий
  include guard вокруг повторяющегося `BlackboardSignalFunctions`;
- `Source/core/Functions_static.cpp`: в `ApplyQueuedHooks` идентификатор модуля
  определяется через локальную статически связанную `QueueHook`, вместо
  импортированной `QueueHookInternal`. Сохранение этой правки важно при
  регенерации или пересборке локальной библиотеки.

В наборе заголовков 0.5.1 совпадают 833 файла, отличаются только два guard
выше. Заголовки, добавленные в 0.5.1, — `AI/TaskPathfinder.h` и
`AI/TaskRepertoire.h`; оба присутствуют локально.

`Inventory.h`, `Item.h`, `Research.h`, `Character.h`, `GameWorld.h`,
`SaveManager.h` и `SaveFileSystem.h` одинаковы в официальных 0.5.0 и 0.5.1 и
совпадают с локальными копиями после нормализации окончаний строк.
Индивидуальные исходные SHA-256 сохранены в JSON проверки.

## Импорты и пределы проверки совместимости

Таблица экспортов DLL прочитана непосредственно из PE, без ограничения числа
имён библиотекой pefile. Локальная `.lib` проверена через VC10
`dumpbin /linkermember:2`; из результата выделены имена `__imp_*`.

- Установленная DLL и официальная 0.5.0 экспортируют 10131 имя.
- Локальная `.lib` содержит 10131 соответствующее импортируемое имя.
- Разность наборов в обоих направлениях пуста.
- В официальной DLL 0.5.1 — 10191 имя: 60 дополнительных, без удаления имён 0.5.0.

Нужные текущему исследованию функции уже доступны в установленной 0.5.0:
`Inventory::buyItem`, `InventoryItemBase::getAvgPrice`, виртуальная и
невиртуальная формы `InventoryItemBase::getValueSingle`, методы Research.
Название базового класса здесь существенно: искать эти экспорты только по
`@Item` было бы ошибкой.

Совпадение экспортов подтверждает наличие импортируемых символов. Оно не
доказывает поведение торговой операции, смысл `isPlayer`, владение предметом
после split/merge, оплату или безопасность повторения после частичного сбоя.
Для этих вопросов по-прежнему нужны чтение native реализации и проверки
игровых результатов. Объявление в SDK не заменяет такой контракт.

## Решение для DynamicFactions

Сохранить действующие пути заголовков и библиотек, локальные исправления и
установленную DLL 0.5.0. Текущие импорты согласованы с ней; необходимые
заголовки общие для 0.5.0/0.5.1. Исправлен только устаревший комментарий
`ours/build.ps1`. Переход всех модов на новый SDK, замена общих библиотек и
обновление DLL игры в эту работу не входят.

Все загрузки и материалы проверки изолированы в
`D:/DEV/Kenshi/tools/_codex_work/sdk-audit-20261030`:
`official-releases.json`, `SDK-AUDIT.json`, `SDK-BINARY-MANIFEST.json`, исходные
архивы и распакованные официальные релизы/исходники. Общие зависимости и
файлы установленной игры при проверке не менялись.
