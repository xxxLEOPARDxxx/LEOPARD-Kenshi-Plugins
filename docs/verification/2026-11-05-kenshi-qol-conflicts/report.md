## Перф/жизненный цикл: препятствия прямому копированию

1. **Постоянные jobs/save изменения даже при OFF.** Q.cpp:1479–1491 регистрирует291/292/293 на TitleScreen независимо от трёх job toggles. Q.cpp:871–903 всегда вызывает convertLegacyDitchDutyJobs, удаляет все native242 perma/transient rows и добавляет293 по shop subject; отсутствие source/version marker означает, что не доказано, что это только legacy Q rows. OFF не возвращает исходный save. Нужны opt-in migration, ограниченный scope, backup и план disable/uninstall с уже сохранёнными custom rows.
2. **Частичный startup не атомарен.** Q.cpp:398–410 три InstallCustomTaskTypes соединены &&; первая уже может быть установлена, следующая отказать. Регистраторы продолжаются без проверки g_customTaskTypeFactoryPatched. Недостающий hook/export не отключает весь зависимый набор. Для переноса нужен paired capability gate: profile, originals, factory, registry, captions, input, score, persistence — всё готово до первой мутации/создания job.
3. **Hardcoded main EXE/ABI.** Q.cpp:386–507,535–562 и TaskTypeFactoryPatch.h:13–18: allocator IAT2246180, ctor332000, TaskData funcs60DF70/26003, registry1CE80F0, hand thunk215E4, vtables16BD798/16BE4C8/16BCD88, factory/rejoin/epilogue32EBE2/32EBE8/330161. Это новые адреса/byte contracts, не покрываемые автоматически существующим KEO GOG port. Patch checks only6bytes/любое E9, а не EXE identity, callee ABI и предыдущий stub ownership. Duplicate task IDs в другой DLL остаются конфликтом: последняя matching ветка может победить. Общий header упоминает SkeletonRebirth, но не реализует глобальный registry владельцев IDs.
4. **Raw lifetime/caps.** Q.cpp:1178–1188 nav queue/seen хранят ZoneMap* без generation/handle/cap и очищаются только hook LoadingWindow::show. Jobs maps Q.cpp:695–696 хранят hand и raw AI*, не имеют общего save/new-world reset; selective erase915–920 требует дальнейшего tick того же AI. UI g_ordersPanel/g_ordersPanelCharacter971/1005 не инвалидируются destruction/selection teardown; refreshOrdersPanelList может использовать старый panel.
5. **Не считать имя LoadingWindow достаточной save boundary.** Фактический Steam LoadingWindow::show9124E0 — ret0, без `.pdata`. Native generate3AB758 вызывает thunk47677→showLoadingMessage6E9800; последний6E9878 вызывает virtual slot+18. Прямое доказательство, что Q reset hook вызывается ровно один раз при смене мира и никогда при другом показе панели, здесь отсутствует. Не утверждается ни бесконечный rebuild loop, ни гарантированное корректное reset. Для переноса использовать существующий KEO verified save/newGame reset pipeline.
6. **Горячие обходы/аллокации.** AI update906–920 выполняется для каждого не-животного с enabled jobs; маршрут каждый tick создаёт vector и сканирует все permajobs. Sell score1042–1052 создаёт unordered_set и обходит jobs/output/inventory при каждой оценке. deposit569–603 переносит по одному предмету без per-tick лимита. Weight1326–1369 создаёт vector/читает контейнеры; глобальный bool recursion guard1341/1365 не TLS и без unwind restore. DebugLog выключен, но std::string arguments к verboseLog строятся заранее. Это статические риски/сложность, не измеренное падение FPS и не доказательство текущей утечки в игре.
7. **Factory allocation ownership.** TaskTypeFactoryPatch.h VirtualAlloc512 RWX/patch6bytes не имеет teardown; отказ VirtualProtect не освобождает stub. Q.cpp:386–391 выделяет task до проверки Tasker ctor; failure теряет allocation. Переносить только с явным владением/neutralization и failure cleanup; callback code должен жить до уничтожения native task instances/vtable users.

## Безопасный порядок интеграции (позже, после отдельного поручения)

1. Зафиксировать Q source/DLL/license provenance и таблицу capabilities; новые RVA/ABI отдельно проверить Steam/GOG, не расширять unguarded fallbacks. Не менять текущий KEO default behavior.
2. Изолированно исследовать gate registration и no-tracer building-handle refresh: короткие события, отдельные toggles, idempotence/lifetime checks. Зафиксировать оригинальные KEO walls/hold/town policies; не переносить nearest-town overwrite.
3. Рюкзаки: оставить KEO владельцем per-character choice; при потребности в отдельных portrait/drop путях сначала доказать gap, добавить узкий adapter с той же policy. При совместном запуске Q FillBackpackFirst=false. Dynamic weight — отдельный opt-in gameplay module.
4. Auto rebuild **OFF по умолчанию**; единый bounded queue по cell+world generation, только native/game-owned eligible cells, использование KEO cache/force admission/worker budgets; без автоматического global furniture repair для каждой зоны и без самостоятельного второго scheduler. Сначала сравнение save-level navmesh results и frame times.
5. Custom jobs перенести отдельным выключенным module/plugin после полного contract review: save format/task IDs, allocation/vtables, all-or-nothing startup, owner-thread state, stable handles, bounded work, explicit migration. Первым Gather291, затем stocking293 с честным названием/ownership, маршруты292 последними из-за перехвата Shift-click и KEO movement observers.
6. Политика совместимости: один owner для auto rebuild, town assignment и backpack routing; при обнаруженном Q не угадывать версии по имени DLL и не заставлять MinHook-chain доказывать поведение. Использовать предупреждение/ручной явно документированный выбор toggles; feature OFF гарантирует отсутствие новых world/save mutations. Уже сохранённые custom jobs требуют безопасного dormant loader/migration, а не простого удаления DLL.

Никакой из этих пунктов не доказывает связь KenshiQOL с текущей толпой у Скуина или excess squads. Это отдельный аудит. Текущая игра и её конфигурация не проверялись/не изменялись.
