# Dynamic Factions: проверка физической экономики 30.10.2026

Статус: локальная проверочная сборка. Полный игровой рейс и повторная загрузка
с товаром пока не приняты. Публикации Nexus/Steam для DynamicFactions не было.

## Реализация

- Runtime использует экономические правила без почасовой выплаты и без покупки
  абстрактных очков технологий. Стартовый бюджет остаётся явно заданным сценарием.
- Штатный OPERATE_MACHINERY производит настоящую руду. HAUL идёт к жиле,
  переносит фактические единицы в обычный инвентарь/рюкзак, идёт к торговцу,
  передаёт ему товар и получает деньги из его кошелька в казну своей фракции.
- Цена вычисляется в контексте настоящего торговца/города. Глобальное окно
  торговли игрока не используется. Исследованы контракты native функций из
  KenshiLib, включая опасный глобальный контекст getValueSingle(false).
- Передача проверяется по количествам сторон, оплата по обоим кошелькам.
  Подтверждённый отказ компенсируется. Неоднозначная частичная мутация блокирует
  работу без слепого повтора; workFault переживает сохранение/загрузку.
- Старые виртуальные остатки сохраняются совместимо, но не производятся, не
  складываются с настоящим запасом и не продаются. Учёт груза и денег остаётся
  в штатном сейве игры; runtime-задачи после загрузки восстанавливаются из него.
- Метаданные и handles инвалидируются до смены мира. Ready зависит от завершения
  штатной загрузки. Работа не исполняется на паузе или внутри сохранения.
- Один пространственный запрос на шаг фракции вместо запроса на каждого рабочего
  и жилу; рабочий шаг не чаще раза в пять секунд без паузы. Native переносы
  ограничены 64 единицами за вызов. Это границы работы, а не замер времени CPU.
