## Ownership and publication assessment

Work remains plain worker-owned data: no Provider, MainToken, native engine reference or D3D owner is reachable. Main copies source requests into Work; Interlocked state/event handoffs delimit worker mutation and Main acceptance/upload. Release clears encoded/decoded source storage on the worker before advancing. Native metadata tests remain explicitly fake/test-owned; actual Win32 file leases, canonical PNG decoding, bank uploads, raster draws, event query and readback run normally.

Shader bytecode is authenticated and copied into the controller's21920-byte storage before Submit returns. Material/frame/grid are copied. Nonempty slots preserve exact source/selector order, validate all15 role positions, commit every accepted receipt, complete the source bank and then draw. Empty trailing slots retain the last nonempty source while executing the staged carry/tail path. Complete is reached after the event and staging copies. Independent result getters require enabled, current full scope and exact frame, so world/OFF/frame changes cannot bypass withdrawal merely by skipping a later Pump.

Successful ReleaseResult can retain the source bank and authenticated TIFF cache. That ownership remains visible/reserved; OFF/world/source replacement drains it asynchronously. A downstream user must hold/copy borrowed plane buffers before ReleaseResult/Cancel/Shutdown or another job. Current provider/scope/material provenance still comes from the checked host adapter, not this controller.

GPU ownership lives in a separately retained heap. Unknown worker/GPU completion records that heap and Work in the single bounded quarantine; normal C++ controller destruction does not drop their COM ownership. The reservation is the conservative **112,825,820-byte maximum**, not merely whatever remains visible after a helper's failed Init clears partial members. The external ledger still includes all other retained/pending/retired owners under192MiB. A quarantine requires retained/reported debt and restart before admitting an incompatible viewer reservation. This is bounded quarantine behavior, not a claim that every resource is reclaimed after an unproven completion.

All controller/status/destruction calls remain Main-only by contract. Invalid caller thread/pointer use, module unload with an active worker and arbitrary corrupted engine state are outside this primitive's guarantee. Opaque WIC/COM/driver working memory is not a hard64MiB process bound. These limitations are explicit in the reviewed README.
