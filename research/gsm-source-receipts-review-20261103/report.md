## Source and lifetime assessment

Main admission checks nonzero full64-bit world/source/job scope and bounded role/base-pin coherence before provider access. The production provider binds either a retained matching nonmanual ResourcePtr or explicit owned named-file evidence. Unknown/manual/mismatching cases refuse. A module reference and CryptoAPI provider outlive use; retained native resources are destroyed before the profile's module reference. Manager-before-group try-lock ordering is consistent between Snapshot and bank commit, including recursive entry on the same owning thread. Bank transactions release all previously acquired group locks on failure. There is no worker Ogre pointer, String, iterator, callback or retained reference in the copied request.

The runtime profile validates its owning thread/module shape, code-window hashes, exact exported target addresses, member-pointer import/zero this-adjustment, allocator import and all relocated FileSystem vptr entries. Actual container traversal is limited to the checked owning native call while manager/group locks are held. This is an exact-build contract, not a generic defense against corrupted engine memory or a substitute for live shutdown/frame ownership. Native calls and SDK container traversal are not a Windows SEH recovery boundary.

The worker caps one allocation at16MiB and includes `sizeof(WorkerFileLease)` in its64MiB caller ledger. It opens root, ancestors and final file with deny-write/delete sharing, refuses actual reparse handles and wrong object kinds, hashes exact copied content, checks pre/post physical identity/stamps, and keeps the lease through Main acceptance. All copied paths are bounded printable ASCII; unsupported namespace/encoding/length cases refuse. No guessed path fallback, native DataStream, engine call or D3D operation occurs in the worker. Cancellation is cooperative between synchronous calls, not a latency deadline; ownership and publication must be transferred with synchronization and joined before destruction.

Main acceptance refreshes metadata and withdraws exposed bytes on failure. A sealed summary represents **authenticated immutable copied bytes matching a coherent base pin plus a refreshed indexed source identity**, not current disk contents at every later instant and not historical equality to a native GPU texture. Releasing the blob/handles before final bank commit is consistent with that explicitly documented guarantee. The caller must associate the original pins with its owned base capture, pair every receipt with the corresponding successful immutable upload, supply the complete expected role set, invalidate the scope/job on cancellation/world changes, and check fresh metadata at bank commit. `CommitBank` validates every supplied receipt and uniqueness, but does not infer the renderer's missing required roles. It does not publish GPU readiness.

## Performance and practical limits

Storage reads/hashing are bounded, chunked worker work; no world scan, growing cache or per-frame INI polling is introduced. One maximum blob uses256 reads of64KiB plus its final SHA. Metadata work is intended for bounded source jobs: each profile revalidation creates18 hash objects and reads5462 native code bytes, plus bounded name/index/path work. This should not be placed in an unconditional per-frame material loop. All16 role summaries and bank snapshot scratch are fixed-size; callers must include their metadata, other pending blobs and payloads in CPU accounting. Existing/native ResourcePtrs can extend external native resource lifetimes; the checked Main adapter must release them before world/renderer shutdown and keep GPU residency accounting separate under the existing192MiB limit.

The tests establish bounded ownership, guards, source-snapshot semantics and host cleanup paths. They do not establish game FPS, long-run memory behavior, every native race, live resource winner acceptance, adjacent material seam quality or complete atlas publication.
