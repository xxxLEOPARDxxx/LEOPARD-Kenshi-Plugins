# KEO: перенос на GOG — проверка 04.11.2026

Состояние: отдельный аудит, а не готовый GOG-релиз. Проверена текущая KEO
`57724259214d72c240ea37a6a030a4ffea50d522`. Игровые файлы, INI, настройки,
процессы и блокировка неподдерживаемой платформы не изменялись.

## Конкретный результат

- GOG отключён самим оригинальным KEO до установки хуков. Наш MCM этого не
  меняет. Автор также прямо указывает отсутствие поддержки GOG:
  https://github.com/jacobericson/KEO .
- Повторно сопоставлены реальные пары официальных таблиц и экспортов
  KenshiLib 0.5.0/0.5.1. У всех 98 зарегистрированных функций адрес GOG
  отличается от Steam. Встречается девять разных смещений, поэтому общего
  «поправочного смещения» для переноса не существует.
- В текущем manifest 94 строки по всем веткам компиляции: 61 имеет прямое
  соответствие официальному GOG-символу, 33 не имеет. Из 94 строк 60 ещё
  не покрыты собственным registry KEO. Это инвентаризация исходников, а не
  количество одновременно установленных хуков.
- Четыре обязательные точки без прямого символа: `edgeProcess`,
  `nmResultPopulate`, `findPathFull`, `addInstance`. Для них нужны настоящие
  инструкции GOG и проверка входных/выходных контрактов.
- Даже официальное соответствие входа `NavMesh::isLoaded(ZoneMap*)`
  Steam `3AC810` → GOG `3AC430` не переносит внутренние адреса возврата
  `A0EA90`/`3AC822`. То же касается проверки публикации очереди и её
  28 окон инструкций, native helpers, Havok TLS, vtables и inline patches.
- Настоящего GOG EXE в проверенных локальных материалах нет. Два EXE
  установленной игры не являются GOG. Наличие `GOG_1.0.65.br` отдельно
  недостаточно для проверки инструкций и ABI.

Полный актуальный coverage ledger, SHA256 входных таблиц/библиотек и
исходников: `coverage.json`. Полная исходная выгрузка символов сохранена
в `game/_codex_work/20261104-keo-gog-audit/evidence.json`.

## Что требуется дальше

На первом этапе достаточно законно полученного `Kenshi_x64.exe` GOG
1.0.65 и его соответствующего `GOG_1.0.65.br` из используемого пакета
KenshiLib. Ожидаемый MD5 GOG EXE из официального определения версии:
`213349bf76a0a758067f9ed0aef2ab01`. Сборщик дополнительно записывает SHA256
и PE-идентификаторы. Чужие игровые DLL или всю установку сейчас запрашивать
не требуется; модули понадобятся отдельно, только если их реальные
профили отличаются при дальнейшем аудите опциональных функций.

После получения EXE: сначала проверить обязательные неизвестные точки,
настоящие GOG byte windows и внутренние callsites. Затем сформировать
полный неизменяемый GOG-профиль и только после этого разрешать платформу
в gate. Последний этап — запуск именно GOG с MCM и проверка потоков,
переходов зон, сохранения/загрузки и остановки workers. Steam-тесты не
подменяют эту проверку. Исправление спавна Скуина выполняется независимо.

## Офлайн-инструмент

`../keo_gog_profile.py` использует только Python standard library.
Он ничего не запускает, не подключается к процессам, не загружает DLL,
не меняет KEO и не скачивает EXE. Выходной JSON создаётся только новым
файлом, без перезаписи старых доказательств.

```text
python tools/diagnostics/keo_gog_profile.py --exe X:/GOG/Kenshi/Kenshi_x64.exe --rvas X:/GOG/Kenshi/RE_Kenshi/RVAs/GOG_1.0.65.br --coverage tools/diagnostics/keo-gog-20261104/coverage.json --output X:/new-gog-profile.json
```

Результат `gog_image_and_known_table_identified` означает только известную
идентичность EXE и таблицы, а не совместимость KEO. Поля
`native_profile_verified=false` и `runtime_tested=false` сохраняются.
При неизвестном/Steam EXE или неизвестной таблице результат отказной.
32-байтовые окна по официальным GOG entry RVA снимаются только с
распознанного GOG EXE; неизвестные адреса не угадываются.

Проверено: шесть тестов PE64/границ/отказов/сохранения отчётов проходят.
На реальном установленном Steam EXE сборщик правильно отказал в GOG
идентификации, хотя передана настоящая GOG-таблица. Реального GOG
запуска и подтверждения GOG-инструкций нет.

Перф/владение: инструмент вне игры, без потоков и игровых callbacks;
чтение ограничено 128 МиБ для EXE, 400000 байт для таблицы и 4 МиБ для
coverage, максимум 512 строк/64 символа на строку. Он не добавляет
работу ни в кадр, ни в ИИ, ни в сохранение.
