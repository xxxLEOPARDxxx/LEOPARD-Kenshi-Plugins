# Native capture feasibility probe

Private diagnostic build only. The original read-only task has ended. On2026-11-01 the user authorized continued satellite rendering work; root installed this diagnostic for controlled manual capture. One manual Ctrl+Shift+Y request, with Kenshi focused and global map open, captures ONE 512-square diagnostic image plus GBuffer evidence, not an atlas. Modes compare main-camera control, independent-camera control, independent orthographic, independent orthographic with temporary Renderer::camera binding, and actual-main-camera orthographic. Every request uses the same fixed global 1024-metre grid and Y=4000 reference; no terrain-height fitting, character teleport, simulation activation or time changes.

The probe uses the actual game workspace definition; disables only its own GUI node (MYGUI is a custom pass, so viewport overlays are insufficient), freezes HDR MIN/MAX luminance to the same positive value inside the synchronous nested update, and restores it before original main-view passes. A camera/renderer-pointer scope restores every property it changes on C++ exception paths. Unsupported custom projection/view/reflection/window/oblique states are rejected rather than altered. The main workspace listener forwards the previous listener and is detached after one request. Probe resources are destroyed in the next native map update, outside compositor iteration. Main/probe GBuffer texture aliasing is rejected.

All visual operations must run on the HWND owning thread. Exact on-disk RE image SHA-256, loaded PE header and selected unhooked native code bytes are guarded. No raw native address call: normal KenshiLib/Ogre exports only. Native code offsets are used for comparison and the verified DistantTown POD layout only.

Own-camera black cause is an unproven hypothesis, not a claimed fix. Compare GBuffer statistics against final output and compositor pass camera pointers. The installed lighting shader reconstructs positions along perspective rays (`deferred.hlsl:156-159`), so native orthographic lighting itself may be invalid despite correct geometry. The probe records this limitation.

Optional existing-proxy experiment stays OFF by default. Only already allocated, stable, mesh-loaded DistantTown Ogre::Entity resources from bounded native town handles can have their Ogre visibility temporarily enabled/restored. Never call Town::showDistantTown(true) for a missing proxy: it allocates/loads/rebuilds and cannot be fully restored by hiding. No all-world/model/player-base coverage is claimed.

Verification before root may choose installation: VC10 /GL /LTCG build, exact native import audit, extracted fixed-grid/projection tests, restoration/source contracts and independent review. Runtime image/visibility/FPS proof remains pending until root explicitly installs/runs the one-shot probe.
