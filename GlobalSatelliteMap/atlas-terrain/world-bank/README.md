# Single-SID staged terrain source bank

`WorldSourceBank.h` owns one reusable D3D11 material bank. It implements the immutable base-snapshot recipes from `../world-material/WorldMaterialPlan.h`; it does not establish the current game's resource winner, decode images, open files, draw, or integrate Main/probe rendering. The only accepted `SourceEpoch.profile` is `PinnedBaseSnapshot=1`. Epochs are nonzero 64-bit caller generations, not evidence that a mod/resource group is currently authoritative.

The source payload is exactly **83,885,956 bytes**: six BC3 and six BC1 2048 layers with the original nine resource mip levels (50,331,456 bytes), regional painted overlay/color with full mip chains (27,962,024), global blend with full chain (5,592,404), the original 4×4 selector (64), and zero interior texture (8). Slot t7 aliases t0. Unused compressed layers repeat the first authenticated bank entry; every layer must be uploaded. No second source bank is allocated when stages change.

The source alone must fit 90 MiB. `Ledger` separately lists every other live owner: `retained`, `carry`, `raster`, `outputs`, `readback`, `pending`, `retired`, and `other`. `Fits` checks their overflow-safe sum plus this bank against the existing 192 MiB cap. It runs before allocation, stage mutation, upload, completion, acquisition and CPU role patching. The bank cannot infer undisclosed caller resources or driver allocation overhead. The existing roughly189 MiB viewer reservation cannot coexist with this bank. Retained SRVs/context bindings can keep a cleared bank alive: charge that payload as retired until those references are released; clearing this C++ owner alone does not prove GPU release.

## Serialized call sequence

1. `Sources::Init(device, epoch, ledger)` allocates the fixed payload, retains the device and initializes neutral interior data. `Ready` remains false. A failed allocation releases partial ownership.
2. Build an actual cell `WorldMaterial::Plan` for the same epoch. `BeginStage(plan,epoch,slot,ledger)` independently rebuilds and compares the recipe, refuses empty/unsupported stages, invalidates the previous lease and uploads the region's original selector table. Slots remain in original selector order; do not deduplicate repeated slots or omit a nonempty code merely because its weight is zero.
3. A bounded worker supplies one copied payload at a time. `ExpectedDds` identifies the exact encoded asset for each kind/layer; `UploadDds` verifies the entire file size/SHA and strict DDS shape, then uploads mips0..8. `ExpectedRgba` identifies the authenticated decoded base pixels and encoded provenance; `UploadRgba` verifies decoded size/SHA, uploads mip0 and generates the full native-format mip chain. Decoding and encoded-file authentication are caller/worker responsibilities. The header retains no blob. DDS inputs are at most5,592,560 bytes; the largest decoded image is16 MiB. No all-SID CPU bank is required.
4. All12 compressed layers and all required RGBA sources must be present before `Complete`. Regional paint is reused within a region and invalidated on region change; global blend is retained. `NeedsRgba` describes the missing uploads.
5. `AcquireBase` returns borrowed SRVs and exact stage identity. `PatchRoles` accepts the3856-byte native pixel constants and replaces only the six indices in each original row's diffuse/normal eight-float role block. The two remaining floats, all other pixel constants, original selector codes/weights, and all15 vertex distortion rows remain untouched. The caller must still supply the original material parameters and painted-tile origin for that region.
6. Before each serialized renderer step, reacquire the matching stage and validate its lease. No bank mutation may race a draw or a worker. No lease may outlive its owning `Sources`. Release renderer/context references before reusing or clearing resources.

`Bindings` includes full source epoch/profile, region/cell/slot/original row, stage revision and allocation token. `ResourceToken` is stable across `BeginStage`, increases after successful clear/reinit and refuses exhaustion; it prevents replacement of a bank with the same epoch from impersonating the previous allocation. `Device()` is borrowed. `CurrentStage`/`LeaseCurrent` expose only ready, matching identities. Independent material generation remains the renderer's responsibility. Empty trailing stages can reuse the last nonempty bank while the staged shader copies carry; the bank itself never accepts an empty computed SID.

Every update temporarily disables and exactly restores a foreign predicate, so false predicates cannot suppress upload/mip generation. Pipeline bindings are never changed. Writable aliases through RTV/DSV/CS or OM UAV are refused before commands; read-only SRV bindings are preserved. Detected post-command device-health failures latch the owner broken/unready until `Clear`. All resources remain charged while broken. Immediate-context operations must run on the caller's serialized render thread; this header does not provide synchronization or call native/engine APIs.

## Reproduction and evidence

Run bundled Python `run_tests.py` from this directory (VC10 x64/SDK7.1 required). If pins are absent, it runs `generate_pins.py`, which authenticates all129 actual PNG files against the pinned region catalog, emits decoded SHA profiles, and saves only five real test images in this folder's ignored `_generated`. Pillow is used offline; production decoding remains outside the GPU owner. Tests load actual authenticated DDS paths from the game's base-snapshot files. No process or installed setting is changed.

The WARP test covers real region3,3/cell10 (two SIDs) and region6,6/cell3 (four SIDs), all six ordered stages, all648 compressed layer/mip subresources, exact decoded mip0 pixels, generated final mips, selector/interior bytes, row remaps, cross-region paint invalidation, foreign false predicate/full pipeline preservation, aliases, full64-bit epochs, stale leases, repeated acquisition/COM balance and shared-ledger boundaries. Test observers are charged separately (largest readback16 MiB). Fault tests cover14 allocation sites, Init health, five later health paths and both monotonic counter limits; functional and cleanup/latch mutants must fail runtime assertions rather than fail compilation or crash.

This establishes an owned, authenticated **base-snapshot source primitive**. It does not prove active mod winners, adjacent paint-region render parity, arbitrary material constants, complete terrain imagery, game performance or absence of all runtime leaks. A production current-source receipt and complete renderer/residency scheduling remain required.
