# Terrain HDR local-light layer

This isolated D3D11 component adds copied registered native point/spot lights to a terrain HDR block **before opaque water and before tone/exposure**. It does not discover lights or call the game. Unregistered/unloaded lamps, wall/roof shadows and local illumination of opaque water are outside its contract.

## Caller contract

1. Obtain a coherent `NativeLocalLights::Snapshot` on the serialized render thread. Its value-only data and generation must remain unchanged throughout Render.
2. Supply `ProvenMapping` only after independent coordinate registration. Its default is unverified. Set its generation, exact copied `SourceSceneOrigin[3]`, and explicitly proven raw-scene-to-absolute-GST translation. The layer does not infer that translation from origin, camera or shared parameters. A rebase or generation change requires a matching new snapshot and proof.
3. Call `Layer::Init(device, bytecode, bytes, callerOwnedGpuBytes)` once. Use the freshly compiled `_generated/LocalLights.cso`; production C++ has no file I/O or shader compilation. `Layer::Clear` releases all private COM objects.
4. Describe the selected GST plane with `Region`: absolute input-plane minimum X/Z and spans, selected source side256/512/1024/2048, and integer block origin. For an actual256x256 GST window texture, pass that window's absolute bounds, sourceSide256 and origin0; do not pass the whole primary span. Rows advance toward positive Z. A block is at most256x256. Sample centres are `min + (sourcePixel + .5) / sourceSide * span`.
5. Pass four exact SRVs: caller-owned block HDR RGBA16F, decoded GST material RGBA16F, normal/coverage RGBA8, and absolute-height R32F. The last three describe the complete selected source side. HDR input/output are the same resource; the layer accumulates in place. Input/output must share the Init device, be ordinary single-mip/sample/array textures, and have no active RTV/DSV/UAV write binding.
6. `Render(false, ...)` returns S_FALSE before inspecting any argument/context. Enabled Render refuses unproven/mismatched mappings, budgets, formats, source bounds, devices or write aliases. No intersecting lights also returns S_FALSE with unchanged HDR. Errors must be reported by the caller. A device failure after dispatch can leave a partial HDR result; regenerate terrain before retrying or displaying a terrain-only fallback.

The shader uses the native `CalcPunctualLight` implementation, native piecewise range attenuation, native spotlight cosine/falloff and the snapshot's effective power. Terrain metalness is0. Its view direction is explicitly parallel top-down `(0,1,0)`, rather than an invented native camera. It preserves original HDR alpha exactly; zero coverage or nonfinite/degenerate source pixels retain the full original HDR value. Decoded linear material values above1 remain unclamped. The degenerate zero light-distance case conservatively contributes zero.

## Bounds, work and lifetime

All up to4096 admitted values are preflighted and conservatively culled in X/Z against the block. Every intersecting value is processed in successive32-light batches. There is no32-total limit or silent truncation. A final partial batch is dispatched. Each batch writes private scratch and copies only the requested block back to caller-owned HDR before the next batch.

The cap aliases the single authoritative `AtlasView::GpuCap`; split-cap mutations are rejected. Private GPU payload is exactly **526,416 bytes**:256x256x8 RGBA16F scratch plus2128 bytes of constants. The supplied caller-owned payload plus this amount must fit the inclusive192MiB cap, checked both at Init and each enabled Render. This ledger counts explicit texture/buffer payload; driver/COM/shader overhead is not measured. Snapshot CPU storage belongs to the caller and is documented separately.

Init creates the shader, one CB, one texture and one UAV. Render creates no D3D resources, has no C++ heap allocation, retains no snapshot/native pointer, and performs no scene enumeration or file I/O. CPU work is bounded by two4096-entry passes with fixed stack storage. The maximum shader workload is still substantial:4096 intersecting lights times256² pixels, up to128 dispatch/copy pairs. Range/normal guards avoid most distant BRDF evaluations, but this is not a GPU time bound or FPS proof. The caller must schedule updates deliberately and limit visible dirty blocks; do not blindly run this on every frame/block.

The helper saves/restores compute shader/classes, CB0, affected SRVs/UAV and predicate. Read aliases of the verified owned HDR output are scoped off all six shader stages and restored exactly, including PS7. Existing write aliases are refused. Native UAV append counters are preserved by restoring with null initial-count arguments. Only owned scratch/HDR resources are written; supplied terrain/material SRVs are read-only. Serialize with the native render context and discard/reinitialize on device replacement.

## Fresh offline verification

Run `run_tests.ps1` using bundled Python, FXC, VC10 x64 and SDK7.1. **169,219 WARP checks PASS; eleven compiled functional mutants are rejected.** The entire adapter and each C++ mutant also compile with the actual native SDK headers. Source fixtures make no game calls or UI/process changes.

The runner verifies all seven native shader-source pins, extracts the unchanged attenuation/BRDF tail, and freshly compiles the **original installed `light_fs` pixel shader** twice (point/spot). It separately verifies actual DXBC constant offsets and bindings. Eleven comparisons exercise point/spot, range branches, power, reflectance>1, nonzero selected-source origin, explicit nonzero translation and a contributing light at index4095. The raster oracle retains native YCoCg decoding, perspective reconstruction and native view direction, using a distant262144-high camera to approximate the declared top-down view. Interior pixels have maximum absolute HDR delta **0.0009765625**, below the asserted.002 bound. This finite fixture approximation does not prove native full-frame/projective equivalence.

Other cases cover32/33/64/4096 batch accounting, spatial rejection, source validity/coverage, native context and six output aliases, append counter7, write-bound sources/output, foreign devices, exact inclusive memory limit, invalid generation/origin/proof, OFF and allocation-free warm Render. Mutants remove the4096 traversal, mapping proof, context restore, budget, power, spot falloff, range attenuation, preserved coverage, invalid-source guard and coordinate translation; each must compile and fail the matching real test.

The component has no runtime coordinate/render integration, live frame-time/long-session memory or full native-image acceptance in this report.
