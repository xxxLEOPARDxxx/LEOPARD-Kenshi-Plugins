# Bounded passive TownList diagnostic

2026-11-02. New standalone header only; no viewer/main integration, game/native getter call, plugin build or installation performed here.

`GsmTownDiagnostic::Read(enabled, sharedKing, engineBase, sourceVerified, stats, candidate)` returns S_FALSE when disabled, E_ACCESSDENIED when source verification/profile fails, S_OK for a complete census (including no candidate), and a failing HRESULT for malformed, inaccessible or changed source data. Outputs are cleared before every attempt and published only after the final checks. The returned const pointer is borrowed for immediate synchronous use in the caller's already serialized world callback; no native pointer is retained by the helper.

The caller's verified source profile must include the exact current RE_Kenshi executable SHA256 `504b362cde850d56afb1cea6f5b7b0ee014d9dd7b47e188599d91c804502cd3e`. Each enabled/verified call also compares five exact 24-byte code windows at B85F0,8679BD,927E08,927E20,253A6 and the primary Town vtable1734C08+268 entry against engine+253A6. No per-call file I/O or native function is used; no cached native profile/object state exists.

Native provenance: `atlas-models/_generated/passive-town-selection.json` proves SharedKing+8 owns TownList, the native getAllTowns result starts at TownList+50, count is uint32 at+58 and its pointer array at+60. `town-vtable-types.json` distinguishes primary Town vtable1734C08 from TownBase1733FA8. Existing native proxy evidence establishes Town+4F8, proxy owner+0/state+8/entity+10. The offline test independently checks the current full EXE hash, all five code windows and primary vtable thunk.

The helper copies at most4096 pointers into32KiB stack storage. It examines only that copied list, admits only the exact primary Town type, and counts nullTown, otherType, missingProxy, ownerMismatch, state0/1/2/3, otherState, state3-nullEntity and valid candidates. `state[3]` includes owned state3 entries with null entity; `nullEntity` is that unavailable subset. The first owner-matching state3/non-null-entity candidate wins. No town position getter, visibility/load/show/rebuild, mutation, allocation, source enumeration, Ogre call or worker access is introduced.

Before publication SharedKing→TownList, count and array must still match. The returned candidate's Town vtable, proxy link, backpointer, state3 and entity identity are checked again. Native scalar/pointer loads are volatile to require actual rereads under optimization. This is neither a lock nor concurrent-destruction safety; the caller must preserve synchronous owner lifetime. Mutations of unrelated list elements in place without a header change are outside this coherence check. The debug caller should invoke at most once per five seconds, not per frame. Output metadata is a fixed52 bytes plus a borrowed pointer; transient pointer storage is32KiB, with no heap/COM/GPU resource ownership.
