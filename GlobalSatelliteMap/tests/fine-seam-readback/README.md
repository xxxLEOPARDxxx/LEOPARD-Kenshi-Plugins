# Fine seam pixel readback

`../../GsmFineSeamReadback.h` is an isolated diagnostic helper, without viewer integration. It does not fix a seam. The caller chooses two current final colour textures after its own world, demand and producer-idle checks.

## Caller contract

- `Request::Begin(device, a, b, otherGpu, otherCpu)` accepts exactly two distinct, same-device, default-usage 256×256 `R8G8B8A8_UNORM`, single-mip, single-sample textures. It rejects writable pipeline aliases. Call on the checked render thread with stable source contents through `Begin`; the helper pins both source COM identities until known query completion. Copy commands precede later source changes on the same immediate context.
- It owns two read-only staging textures and one event query. It temporarily disables and then restores native predication, leaving all other pipeline bindings unchanged. There is no `Flush`, wait, filesystem, engine call, worker launch or polling loop in production code.
- `Poll(blob, otherCpu)` must be on the same thread. `S_FALSE` means retry a later frame. Query uses `DONOTFLUSH`; maps use `DO_NOT_WAIT`. Once complete, `S_OK` publishes an independent heap blob: `Data(0)` and `Data(1)` each contain exactly 262144 tightly packed RGBA8 bytes. Empty input Blob is mandatory; no overwrite/repeated publication.
- `GpuBytes()` counts 524288 staging bytes. `PinnedSourceBytes()` additionally reports 524288 existing source-output bytes until known query completion; count this separately when source cache ownership can retire, or conservatively count it again from Begin. It becomes zero at known completion and stays nonzero on an unknown query error. It does not claim new allocations. `CpuBytes()` includes the fixed Request owner and conservatively the same 524288 staging host bytes; it does not double-count source pins. Additionally count `Blob::OwnedBytes()` once output exists. `otherCpu` excludes this Request/empty Blob, but includes all unrelated retained owners. Inclusive cap boundaries are checked before allocation. The caller reserves staging plus potential source-pin debt before Begin if using that conservative policy; Begin itself checks the actual new staging allocation against its supplied aggregate.
- CPU budget pressure or payload-allocation OOM after query completion returns `E_OUTOFMEMORY` while leaving the request retryable. Source pins have already retired at this known fence. A partial successful Map is always unmapped, even if the second Map is pending or fails.
- Query/Map terminal errors are latched: `Failed()` and `Error()`. Unknown query completion retains source references and staging/accounting. Retain the whole Request and its debt while the caller cannot prove safe retirement. `Clear()` is explicit cancellation/final teardown, **not** a fence proof; D3D11 defers destruction of resources referenced by queued commands. Callers using a stronger known-completion retirement policy must not use `Clear()` to pretend an unknown fence completed. The destructor has the same explicit-teardown semantics.
- `Clear()` releases only owned references, allows reuse and does not invalidate a completed independent Blob. `Blob::Clear()` releases its own payload.

## Focused verification

Run `run.py` with bundled Python. VC10 `/Od` and `/O2` test the actual production header against D3D11 WARP: complete context/predication equality, pinned source reference counts, two distinct continuous colour fields, refusal and inclusive budget boundaries, CPU retry and output independence. A separately generated header replaces individual D3D/allocation calls with test-only fault shims; all other calls remain real WARP operations. This checks pending/failed query, second-map pending/failure, partial staging/query creation and payload OOM. Three functional mutants must fail the controls. Test harness alone flushes and waits for WARP; the helper does neither.

`verification.json` records current source/test hashes. Generated executables are small local test artifacts, not a mod or publication package.
