# Native model GBuffer decode and geometry merge

This isolated256x256 D3D11 compute layer converts an already rendered native DistantTown GBuffer into decoded linear material RGBA16F, normal/coverage RGBA8 and absolute-height R32F. It merges in place against the existing terrain or earlier model surfaces. It performs no native discovery, mesh loading, CPU readback, world activation or viewer integration.

## Interface and registration

`Layer::Init(enabled,device,code,bytes,callerOwnedGpuBytes)` creates three reusable UAV scratch textures and a64-byte CB. Explicit OFF returns S_FALSE before querying the device or allocating resources. `generate_shader.py` emits `_generated/ModelDecodeShader.h` with `AtlasModelDecodeShader` and the corresponding CSO. It pins/copies the existing production `GlobalSatelliteMap/shaders/GBufferDecode.hlsl`, pins the three original DistantTown source files and freshly compiles the unmodified native vertex/pixel shaders for tests. No existing generator is edited.

`Layer::Render(enabled,packet,view,footprint,mapping,sources[6],outputs[3],callerOwnedGpuBytes)` consumes the SAME packet/View that produced the supplied native Raster GBuffer. Calls must be serialized; the caller owns that association and frame/world lifetime. This helper cannot infer which packet previously rendered an arbitrary supplied texture.

`ProvenMapping` defaults to unverified and must remain so until independent paired registration proves its translation. It carries generation, exact copied packet SourceSceneOrigin and explicit raw-scene-to-cache XYZ translation. No automatic origin addition or save fingerprint is inferred. Packet, View and proof generations must agree, and the proof's origin must match the packet byte-for-byte.

`Footprint.minX/minZ` are the absolute minimum coordinates of the destination256-square input window. Width/height are its world spans, not pixel counts. Near/far describe the actual native orthographic View. NearClip is used to validate that matrix; raster hardware already clips the geometry, and shader limits[1] is unused. Construct the corresponding camera with **this exact arithmetic order**: `rawMin = absoluteMin - translationXZ`, `rawCameraXZ = rawMin + span*.5`. Use `AtlasModels::TopDownView(rawCameraX, rawCameraY, rawCameraZ, width, height, nearClip, farClip, generation, view)`. The helper verifies that full matrix exactly; unsupported perspective/rotation/projection or a different target window refuses. Rows advance toward positive Z, columns toward positive X. Raw pixel centres are `rawMin + (pixel+.5)/256*span`.

SRVs0..2 are native Raster packed albedo/metal/gloss RGBA8, normal RGBA8 and radial distance/far R32F. SRVs3..5 are existing decoded material16F, normal/coverage8 and absolute height32. All are exactly256x256, single mip/sample/array and the same device. Outputs0..2 MUST be those same decoded resources. Pairwise native-plane identity aliases, native source/output aliases, any write-bound input/output, wrong formats/devices or budget overflow refuse before writing. All six-stage read aliases of the owned decoded outputs are temporarily removed and restored.

Enabled success returns S_OK. Explicit OFF returns S_FALSE before inspecting packet, projection or resources. Errors are returned for the caller to report. Device failure after dispatch/copies can leave a partial three-plane result; regenerate the terrain window before retrying or displaying a fallback.

## Packing, radial reconstruction and merge

The exact existing chroma helper reconstructs the native checkerboard YCoCg colour, including its edge-directed four-neighbour weights. Material alpha is native GBuffer0 gloss; normal alpha is NOT model coverage. Nonzero finite native radial depth supplies geometry coverage. Normals are decoded, normalized and reencoded with explicit coverage1. This is the decoded GST unit-normal contract, rather than bitwise preservation of the native buffer: the native DistantTown shader can emit nonunit transformed normals. An actual oblique native normal fixture verifies the normalized result within1UNORM; it is not an exact original-normal-byte claim. No gamma conversion, colour substitution or reflectance clamp is introduced.

For the explicitly validated downward view, reconstruct `vertical = sqrt((depth*farClip)^2 - dx^2 - dz^2)`, then `absoluteY = rawCameraY - vertical + translationY`. The positive downward branch follows the supplied top-down camera. A negative, nonfinite or ill-conditioned root retains the old pixel; it does not invent height0. Radial distance may exceed axial farClip near orthographic corners, so depth>1 is not automatically invalid.

Float32 depth storage, multiplication and subtraction lose precision when a radial square nearly cancels the horizontal square. The shader uses a conservative16-epsilon arithmetic interval, rejects roots within it and derives a Y uncertainty interval. Covered terrain/earlier models are replaced only when the new surface's lower confidence height exceeds the old height. Coplanar/uncertain ties retain the old geometry. The stored selected height is the reconstructed height, not the lowered comparison bound. This is a bounded conservative policy with selected native-float fixtures, not a formal error guarantee for every possible native transform/source magnitude.

Zero/invalid model coverage and higher existing terrain retain **all three** old planes. An uncovered existing pixel may accept valid model geometry. Sequential calls can therefore merge supported towns into one decoded window without a model CPU image cache. This is an additive geometry compositor: it cannot erase a previously merged model when that model moves/disappears or the admitted set changes. The caller MUST restore the pristine terrain/window-generation base and replay the current model set for such refreshes, and invalidate it on world/load/generation/source changes. Preserving old pixels is not a model-removal cache policy. A coarse window still samples geometry at256 pixel centres: subpixel roofs/walls may disappear, and packed chroma at geometry edges has the original finite-resolution limitations. This helper does not manufacture missing buildings or high-frequency detail.

## State, memory and work

Private payload is **1,048,640 bytes**:256²×(8+4+4) plus64-byte constants. Inclusive checks use the authoritative `AtlasView::GpuCap` (currently192MiB), both at Init and each Render. The caller must count every other live/pending/retired allocation, including native Raster outputs and local/water scratch. Driver/shader/COM overhead and borrowed native geometry retention are separate from this explicit payload ledger.

Render performs one fixed32×32 dispatch and three same-size copies, with no heap allocation, resource creation, file read, world scan or game getter. All six SRVs, CS/classes/CB and three touched UAV slots are restored; hidden UAV counters are preserved by null initial-count restores. Predication is disabled only within the scoped operation. Construction and Clear retain no game pointer; Clear releases private COM resources. Serialize with the immediate native D3D context and discard/reinitialize on device replacement.
